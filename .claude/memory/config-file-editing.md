# 設定ファイルを書き直すときに注釈を残す

生成プラグイン coverity-warning-triage で、人も書く設定ファイル（config.yaml）をスクリプトが保存すると、人が書いた注釈が消えていた件を直したときに分かったこと（2026年11月）。直し方は、ユーザーが「ライブラリを足さずに、注釈を元の場所に残す」を選んだ。

## 起きたこと

- ct.py の画面の保存と `ct.py set-verify` は、`yaml.safe_load` で読み、`yaml.safe_dump` で全体を書き直していた。行の頭から書いた注釈の行だけを集めて先頭に付けていたので、それらはファイルの先頭に移り、字下げした注釈の行と行の終わりの注釈は消えた。
- /coverity-setup の手順書（SKILL.md）の例は、統合と検証の設定の行の終わりに注釈（「# 統合を使う」など）を付けて書く。エージェントがそのとおりに書くと、その注釈も次の保存で消える作りだった（実際のモデルで /coverity-setup を動かして確かめてはいない）。

## 作り方（plugin-market-place の `plugins/coverity-warning-triage/skills/coverity-triage-scripts/scripts/ctlib/yamledit.py`。コミット 07ea7f9、f10d56c）

- pyyaml の `yaml.compose` が返すノードの位置（`start_mark`・`end_mark`）で、ファイルの中の値の場所が分かる。変えた値の範囲だけを書き換えると、ほかの行と注釈はそのまま残る。新しいライブラリは要らない。
- 注釈の持ち主を決めておく。行の終わりの注釈は、その行の設定の項目かリストの値のもの。続いた注釈の行は、次の値の行のもの。消してよいのは、消した項目や値の注釈（行の終わりの注釈と、空の行をはさまずにすぐ上にある注釈の行）だけ。
- リストは、値ごとに前の値と対応づけて（`difflib` で並びが同じもの、次に同じ値、次に置き換えた部分の値を順に）、新しい並びで書き直す。各値は、前の値との間の行（空の行と注釈の行）と一緒に動くので、並べ替えても注釈が付いて動く。
- ファイルにない設定の項目は、既定の値から変えたときだけ足す。全部書き出すと、人が書いていない項目が増える。逆に、全体を書くときに外す項目（空の値など）でも、ファイルにあって意味が変わらないなら、書いてあるまま残す。
- 書いた中身は、書き換えの手順とは別のやり方で確かめる。読み直した値が新しい値と型まで同じか、同じキーが2つないか、元の注釈が同じ持ち主の同じ所（行の終わり、または注釈の行の並びの中の同じ位置で、次の値の行との間に空の行があるかも同じ）にあるか。
- 確かめに通らないときと、扱えない書き方（「|」「>」で何行かにわたる値、「&」で名前を付けた値を「*」で使い回す書き方、タグ、文書が2つ以上など）のときは、保存の前に「このファイルでは、注釈は動いたり消えたりします」と知らせ、続けると全体の書き直しに戻す（行の頭から書いた注釈の行は先頭にまとまり、ほかの注釈は消える）。画面は保存の確認を開くときに、コマンドは同意を求める前の `--check` で、同じ書き換えを試して知らせる。
- 先頭の BOM、ファイルの終わりに改行がないこと、引用符の中の `#`（注釈ではない）、キーだけで値のない行も扱う。試験は `tests/stage2/task/test_yamledit.py`（でたらめな組み合わせ400回を含む）。

## 注釈を残せるライブラリと比べて

- ruamel.yaml 0.19.1 と、同じ13の変え方で比べた（ct.py が書く形のファイルに、注釈を11個足したもの）。値を変えただけなら、どちらも注釈はすべて元の場所に残った。設定の項目やリストの値を足したり消したりすると、ruamel.yaml は6つの変え方で、隣の項目の注釈や次の節の前の注釈の行を動かしたり消したりした（節の最後に項目を足すと、次の節の前の注釈の行が、足した項目の上に移る、など）。消した項目のすぐ上の注釈の行は、次の項目の上に付いた。値を変えていない行の書き方（リストの字下げ、長い値の折り返しの位置、注釈の前の空白の数）も変わった。
- ライブラリを足すと、使ってよいライブラリを決めた社内のサーバーから uv が取ってくる PC では、そこにそのライブラリがないとスクリプトそのものが動かなくなる。
- 別のエージェントの点検で、「並べ替えると注釈が消える」「空の行をはさむと書き換えられない」「確かめが、動いた注釈を通す」などが見つかった。書き換えと確かめを別のやり方にしておくと、書き換えの誤りが確かめで見つかり、全体の書き直しと知らせに戻るので、注釈が黙って消えない。
